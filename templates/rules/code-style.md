# 通用代码风格规范

## 注释

- 复杂逻辑**必须有注释**说明"为什么这样做"
- 公开函数必须有 JSDoc 注释
- 不明显的 hack 必须注释原因
- TODO 注释必须带负责人和预计完成时间

## 函数设计

- **单一职责**：一个函数只做一件事
- **可复用**：通用逻辑抽离为工具函数
- **可测试**：函数应该易于单元测试
- 函数长度不超过一屏（~50 行）

## 命名

- 见名知意
- 避免缩写（除非是通用缩写如 `id`、`url`）
- 变量名用名词，函数名用动词

## 错误处理

- 不静默吞掉错误
- 错误信息要明确，包含修复建议
- 关键路径必须有日志

## 项目结构

- 配置文件放项目根
- 业务代码按模块分目录
- 工具函数统一放 `utils/` 或 `lib/`

## Git

- 一个 commit 只做一件事
- commit message 格式：`<type>: <subject>`
- 重要代码变更必须更新对应文档
